Run everywhere

High-level k7e demo path on the usual hosted platforms. Swap in your account, region, and kubeconfig — commands are illustrative, not a full production playbook.

AWS

Amazon EKS

Create a managed cluster, then apply the k7e demo manifests.

  1. Provision cluster with eksctl or the EKS console.
  2. Update kubeconfig for the cluster.
  3. Deploy the demo workload and expose a service/ingress.
eksctl create cluster --name k7e-demo --region us-east-1
aws eks update-kubeconfig --name k7e-demo --region us-east-1
kubectl apply -f https://example.com/k7e/demo.yaml
Azure

Azure AKS

Spin up AKS, pull credentials, ship the same k7e manifests.

  1. Create a resource group + AKS cluster.
  2. Fetch admin credentials into kubeconfig.
  3. Apply the demo and verify pods/services.
az group create -n k7e-rg -l eastus
az aks create -g k7e-rg -n k7e-demo --generate-ssh-keys
az aks get-credentials -g k7e-rg -n k7e-demo
kubectl apply -f https://example.com/k7e/demo.yaml
Google Cloud

Google GKE

Autopilot or Standard — same k7e apply path once credentials are wired.

  1. Create a GKE cluster in your project/zone.
  2. Get credentials via gcloud.
  3. Apply the demo manifests.
gcloud container clusters create k7e-demo --zone us-central1-a
gcloud container clusters get-credentials k7e-demo --zone us-central1-a
kubectl apply -f https://example.com/k7e/demo.yaml
OpenShift

Hosted OpenShift

ROSA, Azure Red Hat OpenShift, or any managed OpenShift — use oc where you prefer it.

  1. Create / open a hosted OpenShift cluster (ROSA, ARO, or provider console).
  2. Log in with oc login (or kubeconfig from the console).
  3. Create a project/namespace and apply the k7e demo.
oc login --server=https://api.example.openshift.com:6443
oc new-project k7e-demo
oc apply -f https://example.com/k7e/demo.yaml
# kubectl works too once kubeconfig is set
Also fine for demos: DigitalOcean Kubernetes (DOKS), Linode/Akamai LKE, or a quick vanilla kubeadm / kind / minikube cluster locally — same kubectl apply once you have a context.
